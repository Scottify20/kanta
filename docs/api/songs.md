# Songs and Media API

**Navigation:** [Home](../README.md) | [API guide](README.md) | [Queue API](queue.md) | [Separation API](separation.md) | **Songs and media** | [Frontend playback](../frontend/playback.md)

Generated output is served through `/media`. The output parent defaults to `backend/separated` and can be changed from the frontend Settings screen. A song is available after its queue task reaches `completed`.

## List processed songs

`GET /api/songs`

Returns manifests for all processed song directories. The frontend Library uses this endpoint. Each returned song can be played directly without reprocessing, or added as a completed Karaoke Queue entry.

## Read a song manifest

`GET /api/songs/{artist}/{album}/{title}`

Use the sanitized path values generated by the backend.

Artist, album, and title are path parameters. URL-encode spaces, brackets, and other special characters, or use the URLs returned by the queue result and manifest.

```bash
curl http://127.0.0.1:8000/api/songs/Artist/Album/Song
```

The response contains:

- `stems`: generated MP3 stem names and URLs.
- `lyrics`: `.ttml` or `.lrc` files, URLs, and per-file `level` (`word` or `line`).
- `lyrics_level`: the best available level, preferring `word`, then `line`, otherwise `none`.
- `lyrics_offset_ms`: saved playback adjustment; positive values delay display and negative values advance it.
- `covers`: extracted album art and URL.
- `master`: URL for the tagged original MP3 copy, when present.

Each media entry has a display `name` and a ready-to-request `url`. The manifest can contain an empty array when lyrics or cover art were not found; that does not mean separation failed.

Example shape:

```json
{
  "artist": "Artist",
  "album": "Album",
  "title": "Song",
  "stems": [
    {"name": "Song (Instrumental).mp3", "url": "http://127.0.0.1:8000/media/..."}
  ],
  "lyrics": [],
  "lyrics_level": "none",
  "lyrics_offset_ms": 0,
  "covers": [
    {"name": "cover.jpg", "url": "http://127.0.0.1:8000/media/..."}
  ],
  "master": null
}
```

## Download a generated file

Use the URL returned by the manifest:

```bash
curl -L -o instrumental.mp3 \
  "http://127.0.0.1:8000/media/Artist/Album/Song/stems/Song%20%28Instrumental%29.mp3"
```

## Directory layout

```text
separated/{artist}/{album}/{title}/
├── stems/
├── lyrics/
├── covers/
└── {title}.mp3 (optional master copy)
```

## Angular manifest usage

```ts
interface SongFile {
  name: string;
  url: string;
}

interface SongManifest {
  artist: string;
  album: string;
  title: string;
  stems: SongFile[];
  lyrics: SongFile[];
  covers: SongFile[];
  master: string | null;
}

getManifest(artist: string, album: string, title: string) {
  return this.http.get<SongManifest>(
    `http://127.0.0.1:8000/api/songs/${encodeURIComponent(artist)}/${encodeURIComponent(album)}/${encodeURIComponent(title)}`
  );
}
```

Select playback stems from the returned JSON:

```ts
const vocals = manifest.stems.find(file => file.name.includes('Vocals'));
const instrumental = manifest.stems.find(file => file.name.includes('Instrumental'));

if (!vocals || !instrumental) {
  throw new Error('Required playback stems are missing.');
}
```

## Typical client flow

1. List or request a song manifest.
2. Confirm the manifest contains both a Vocals and an Instrumental stem.
3. Select the required stem URLs from `stems`.
4. Pass those URLs to the frontend audio player.

The frontend prefers saved `.ttml` or `.lrc` files from `lyrics`. The Braccato parser displays them locally; `/api/blyrics/getLyrics` can serve the same saved files through the lyrics proxy.

Word-timed TTML takes precedence over line-timed LRC. If only line lyrics are saved, the frontend may refresh online while keeping the saved lines as a fallback. A saved word-timed TTML is used directly without another provider request.

## Adjust lyrics timing

`PUT /api/songs/{artist}/{album}/{title}/lyrics-timing`

Store a per-song timing adjustment between `-10000` and `10000` milliseconds. Positive values delay lyric highlighting; negative values advance it.

```bash
curl -X PUT http://127.0.0.1:8000/api/songs/Artist/Album/Song/lyrics-timing \
  -H "Content-Type: application/json" \
  -d '{"offset_ms":250}'
```

The value is persisted in `lyrics/timing.json` beside the lyric files and returned by subsequent song-manifest requests.

## Missing songs and files

The manifest returns `404` when the sanitized song directory does not exist. A missing cover or lyrics file is represented by an empty list. Static media requests return the normal Starlette static-file error when a generated file has been removed.
